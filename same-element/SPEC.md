# Общий элемент — SPEC

## Purpose

Android (and the same web UI) trainer for Mandarin learners who mix up characters that share a component. The learner picks a list — for example every sign with 氵 — then writes those characters the way HanziGarden does: stroke order, direction, and placement are checked. The shared element is already inked, so practice is about the part that distinguishes 江 from 河 from 汗.

Audience: a learner who already meets these signs and needs to stop treating “water + something” as one blob.

## Requirements

1. Ship the 15 element lists from the bundled catalog (水/氵, 言/讠, 火/灬, 囗, 辶, 手/扌, 糸/纟, 心/忄/⺗, 木, 日, 金/钅, 艹, 宀, 女, 土): hanzi, pinyin, Russian gloss.
2. Home screen lists each element with its Russian name and count. Opening one shows every character in that group.
3. The learner selects the training list (all visible, clear, random 8, or individual checks). At least two characters are required. The last selection for that element is remembered on the device.
4. Training shuffles the selected list. Each prompt shows the Russian gloss and pinyin, and does not show the target hanzi until the character is finished or the learner asks to see it.
5. The shared element’s strokes are drawn before the first touch, in a distinct ink. The quiz accepts only the remaining strokes, in their original order, with the same Hanzi Writer grading as HanziGarden (order, direction, placement; backwards strokes rejected).
6. Hint highlights the next remaining stroke. Outline reveals the remaining strokes and counts as help. “Не помню” reveals the hanzi. A finished character with any mistake, hint-outline, or reveal is a miss.
7. After the list, show clean vs missed characters and offer to retry only the misses or the whole list.
8. Element stroke indices are computed from Make Me a Hanzi medians: trust Kangxi `radStrokes` when they match the element’s shape; otherwise search the character (so 杰’s 灬 and 渠’s 木 are found even when they are not the dictionary radical). Every catalog character must resolve.
9. Stroke JSON is loaded with XHR so the quiz works from `file://` inside the Android WebView.
10. Package the web build in `same-element-android` (application id `com.tepmex.sameelement`, display name **Общий элемент**, minSdk 34) and publish a GitHub Pages landing plus the web app.

## Interfaces

| Interface | Detail |
| --------- | ------ |
| Web UI | Vite + React. Routes are in-app state: home → pick → train → summary |
| Catalog | `data/elements.json` — categories with `id`, `element`, `name_ru`, `description`, `characters[]` of `{hanzi, pinyin, ru}` |
| Stroke files | `public/hanzi/<char>.json` generated by `scripts/prepare-hanzi.ts` from `hanzi-writer-data`. Fields: `strokes`, `medians`, `elements` map of category id → stroke indices |
| Local storage | `same-element:pick:<categoryId>` string array; `same-element:results` clean/miss counts |
| Android | `com.tepmex.sameelement.MainActivity` loads `file:///android_asset/www/index.html` |
| Asset sync | `same-element-android/scripts/sync-web-assets.sh` |
| Pages | `/same-element/` web app, `/same-element-android/same-element-android.apk` |

## Data model

- No accounts and no server. Progress is the selection plus clean/miss counts in `localStorage` (WebView DOM storage on Android).
- Stroke geometry is Make Me a Hanzi via `hanzi-writer-data`, not stored in git; `prepare-hanzi` regenerates it at dev/build time.
- A character that sits in two categories (渠, 杰, 蒸) has two index lists. Training uses the list for the category the learner opened.

## UI / UX

1. Paper sheet, cinnabar 米字格, indigo ink for the given element, black ink for the learner.
2. Home: 15 element cards. Pick: searchable checklist and a docked start button. Train: gloss, pinyin, sheet, hint / outline / reveal, then next. Summary: misses and retry.
3. Phone layout fits the sheet on screen; the same screens work in a desktop browser.
4. Android shell is fullscreen, sensor orientation, keeps the screen on.

## Out of scope

- FSRS, Anki, or audio
- Drawing the shared element itself (it is given)
- Lists outside the 15 catalog groups
- Traditional-character variants
- Accounts, cloud sync, Play Store

## Acceptance criteria

1. `bun test` in `same-element` checks element indices for water, speech, fire, grass, wood, enclosure, road, hand (扌 and 手), silk, heart (忄, 心, ⺗), sun, metal, roof, woman, and earth, including 渠’s two different components and 国’s non-prefix 囗.
2. `bun run build` emits `dist/index.html` and one stroke JSON per catalog character.
3. In the browser, choosing 氵, selecting 江 and 河, and starting training shows the three water strokes already drawn and asks for the remaining strokes of a gloss, without printing the target hanzi first.
4. `same-element-android/scripts/sync-web-assets.sh` then `./gradlew assembleRelease` produces a sideload-signed APK.
5. Root `README.md` and `.github/workflows/deploy.yml` include `same-element` and `same-element-android`.
