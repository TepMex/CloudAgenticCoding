# djvu-tui

Монохромный просмотрщик DjVu для Linux и macOS. Показывает исходные страницы
символами Unicode прямо в терминале, в том числе через SSH и tmux. Поддерживает
одну страницу, автоматические развороты, увеличение и перемещение по изображению.

GUI, DjVuLibre, `ddjvu`, Chafa, OCR, графические протоколы терминала и отдельные
файлы шрифтов не используются. Нужен интерактивный UTF-8-терминал, в котором
имеющийся моноширинный шрифт поддерживает Braille и блочные символы шириной в одну
ячейку. Баш/зш запускают обычный исполняемый файл.

## Локальная сборка

Нужен Rust 1.88+ с Cargo и системный линкер для сборки на своей платформе.
Зависимости загружаются Cargo при первой сборке и фиксируются в `Cargo.lock`.
На машине, где запускают готовое приложение, Cargo и исходники не нужны.

Из корня монорепозитория:

```sh
cd djvu-tui
cargo build --release --locked
./target/release/djvu-tui
./target/release/djvu-tui /path/to/book.djvu
./target/release/djvu-tui /path/to/books
```

На macOS бинарник использует только библиотеки ОС. Для второй архитектуры:

```sh
rustup target add aarch64-apple-darwin x86_64-apple-darwin
cargo build --release --locked --target aarch64-apple-darwin
cargo build --release --locked --target x86_64-apple-darwin
```

Для Linux собирайте статический musl-бинарник. Эти команды работают также при
кросс-компиляции с macOS: Rust поставляет линкер `rust-lld` и musl runtime вместе
с целевой стандартной библиотекой; отдельный C toolchain для целевой системы
этому проекту не нужен.

```sh
rustup target add x86_64-unknown-linux-musl aarch64-unknown-linux-musl
CARGO_TARGET_X86_64_UNKNOWN_LINUX_MUSL_LINKER=rust-lld \
  cargo build --release --locked --target x86_64-unknown-linux-musl
CARGO_TARGET_AARCH64_UNKNOWN_LINUX_MUSL_LINKER=rust-lld \
  cargo build --release --locked --target aarch64-unknown-linux-musl
```

Скопируйте `target/<target>/release/djvu-tui` на соответствующий сервер.
Бинарники разных ОС и архитектур собираются отдельно. Папка `target/` игнорируется.

```sh
ssh -t user@server /path/to/djvu-tui /path/to/book.djvu
```

## Управление

| Клавиша | Действие |
| --- | --- |
| ↑ / ↓, Enter, Backspace | Выбор файла, открытие, родительский каталог |
| Space / PgDown, PgUp | Следующий / предыдущий экран страниц |
| `g`, номер, Enter | Перейти к странице; Esc отменяет ввод |
| `+` / `-`, `0` | Масштаб ×1.25 / ÷1.25, вернуться к вписыванию |
| Стрелки при увеличении | Перемещение на 4 колонки / 2 строки |
| `v` | Автоматически → одна страница → разворот |
| `r` | Braille 2×4 → блочные символы 2×2 |
| `d` | Включить/выключить Bayer-дизеринг для полутонов |
| `i` | Поменять местами чёрный и белый |
| `o` / Esc | Файловый браузер; Esc в браузере возвращает открытый документ |
| `?` | Справка; `?` / Esc закрывает её |
| `q` / Ctrl-C | Выход; во вводе номера сначала Esc |

Браузер показывает каталоги, символьные ссылки и файлы `.djvu` / `.djv`
(регистр расширения не важен). Home / End и PgUp / PgDown перемещают выбор.
Ошибки доступа и декодирования отображаются в приложении; `o` позволяет открыть
другой документ.

Первая страница — отдельная обложка; развороты: 2–3, 4–5 и далее. Автоматический
режим включает разворот, когда обе страницы помещаются по ширине в масштабе
вписывания по высоте. Между страницами две колонки. Принудительный разворот
может уменьшить страницы. Последняя непарная страница отображается отдельно.

Увеличение (до 16× относительно вписывания) фокусируется на выбранной странице,
сохраняя центр при последующих изменениях масштаба. `0` возвращает раскладку.
Изменение размера окна сохраняет номер выбранной страницы и ограничивает
прокрутку новыми размерами. Для выбора правой страницы разворота перед увеличением
используйте `g`.

Размер символа берётся из размера терминального окна в пикселях, если он
доступен. Через SSH/tmux эти данные часто отсутствуют; тогда ширина ячейки
считается равной половине высоты. Если пропорции выглядят неверно:

```sh
./target/release/djvu-tui --cell-aspect 0.5 book.djvu
```

`--cell-aspect` принимает отношение ширины ячейки к высоте от 0.1 до 2.0.
`--` позволяет открыть путь, начинающийся с дефиса. `--help` и `--version`
работают без интерактивного терминала.

## Как устроено

`document` скрывает `djvu-rs`: читает документ, учитывает INFO-поворот,
декодирует только необходимый регион и возвращает готовые сетки символов.
`raster` преобразует яркость в геометрические Unicode-символы, не зная о TUI.
`view` рассчитывает страницы, масштаб, физические пропорции и координаты.
Терминальный интерфейс находится в `tui`, с внутренними `browser` и `worker`.

В каждой ячейке восемь отсчётов превращаются в маску Braille либо четыре
отсчёта — в квадранты блочного символа. Otsu-порог считается один раз по
уменьшенной полной странице и сохраняется при прокрутке. Дизеринг 4×4 привязан
к координатам страницы. Пробел обозначает бумагу; вывод содержит только два цвета.
Временный растр хранится в памяти процесса. Терминал получает символы и ANSI.

Один рабочий поток декодирует документ. Очередь хранит последний запрос;
замена отменяет устаревшую работу, а TUI принимает ответ только своего поколения.
Отмена кооперативная: уже начавшийся этап декодирования может закончиться до
следующей точки отмены. Завершение приложения не ожидает его окончания.
После текущего экрана поток подготавливает следующий.

Кэш декодера ограничен 48 MiB, кэш символов — 16 MiB, включая резерв под его
служебные структуры. Это бюджет **кэшей**, а не всей памяти процесса: исходный
файл, активные вычисления и экран также занимают память. Приложение не
перерисовывается на таймере; Ratatui отправляет изменения ячеек по событиям.

Поддерживаются одностраничные и bundled многостраничные DjVu, включая общие JB2
словари. Indirect-документы с внешними файлами страниц получают понятную ошибку.
Текстовый слой, OCR, аннотации, выбор шрифта и сохранение настроек/позиции чтения
в этой версии не реализованы. Мелкий текст целой страницы требует увеличения.
Ограничения обработки: файл до 512 MiB, до 100 000 страниц, до 128 млн исходных
пикселей страницы, оценка декодированной страницы до 512 MiB и регион вывода до
16 млн отсчётов.

## Проверки и замеры

Все проверки запускаются локально:

```sh
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
cargo run --release --locked --example make_fixtures -- target/fixtures
python3 scripts/pty_smoke.py target/release/djvu-tui target/fixtures
cargo run --release --locked --example benchmark -- target/fixtures/large.djvu
```

Генератор создаёт собственные геометрические изображения и надписи, цветную
иллюстрацию, книгу с общим словарём, повёрнутую страницу, indirect-индекс и
скан 2400×3500. Сторонние сканы и шрифты не скачиваются.

19 Rust-проверок покрывают маски символов, геометрию, навигацию, отмену и замену
запросов, реальные кодеки, общий словарь и ошибки. PTY-проверка через стандартную
библиотеку Python проверяет клавиатуру, содержимое экрана, resize, быстрые
переключения, полярность, права доступа, ошибки, Ctrl-C/SIGINT/SIGTERM и
восстановление атрибутов терминала. Проверку прав запускайте без root.

`DJVU_TUI_TIMINGS=1 ./target/release/djvu-tui book.djvu` после выхода печатает
последние измерения открытия, декодирования, символизации и вывода. Отдельный
бенчмарк измеряет 30 запусков с прогретым файловым кэшем ОС; ANSI-вывод направлен
в `/dev/null`, поэтому задержка эмулятора терминала и сети в него не входит.
Результаты и проверенные платформы описаны в [VALIDATION.md](VALIDATION.md).

## CI

Этот Cargo-проект независим от веб- и Android-приложений. Изменения только в
`djvu-tui/**` исключены из push-триггера существующего workflow. Смешанный push
сохраняет обычные selective builds. Rust-сборок, публикации и релизных workflow нет.
