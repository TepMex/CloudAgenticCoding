# Локальная проверка

Проверено 6 ноября 2026. Сборки и проверки выполнялись локально; GitHub Actions
для Rust не добавлялись.

## Среда и сборки

- Apple M4, 16 GiB RAM, macOS 15.5; Rust/Cargo 1.92.0.
- `aarch64-apple-darwin`: release-сборка и PTY-сценарии на основной машине.
- `x86_64-apple-darwin`: release-сборка, запуск через Rosetta на Apple Silicon.
- `aarch64-unknown-linux-musl`: release-сборка с `rust-lld`; PTY-сценарии в
  одноразовом Linux-контейнере, в том числе от UID 65534.
- `x86_64-unknown-linux-musl`: release-сборка с `rust-lld`; PTY-сценарии в
  Linux-контейнере с эмуляцией amd64, от UID 65534.

`file` подтверждает статическую линковку обоих Linux ELF. `otool -L` для
macOS показывает только `/usr/lib/libSystem.B.dylib` и `/usr/lib/libiconv.2.dylib`.
DjVuLibre и GUI при проверках не устанавливались. Для Linux PTY-стенда
использовался `python:3.13-alpine`; Python нужен только проверочному скрипту.

## Функциональные проверки

Пройдены `cargo fmt --check`, `cargo clippy --locked --all-targets -- -D warnings`
и `cargo test --locked`: **19 Rust-тестов**.

Проверяются все 256 Braille-масок и 16 квадрантов, белые/чёрные области,
яркость/прозрачность, порог, стабильный дизеринг при прокрутке, геометрия ячейки,
граница разворота, обложка, последняя страница, масштаб, прокрутка, смена размера
и сохранение выбранной страницы.

Интеграционные тесты создают собственные DjVu: JB2, IW44, многостраничную книгу
с реальными Djbz/INCL, INFO-поворот и indirect-индекс. Проверяются повторное
использование кэша, соответствие региона фрагменту полной страницы, отмена,
повреждённый файл, недоступный путь и неверные координаты. Тест рабочего потока
быстро заменяет серии открытий/рендеров и ждёт последнее поколение.

`scripts/pty_smoke.py` проверяет содержимое экрана и ввод: открытие через браузер,
страницы/развороты, переход по номеру, zoom/pan, оба набора символов, дизеринг,
полярность, справку, смену файлов во время работы, resize до 1×1 и обратно,
ошибки с восстановлением просмотра, повреждённый файл и отказ в доступе.
После `q`, Ctrl-C, SIGINT и SIGTERM проверяются атрибуты termios, возврат курсора
и выход из alternate screen. Проверка прав выполнялась без root на macOS и Linux.

Этот же набор интерактивных сценариев прошёл внутри Linux через tmux и через
локальный SSH с PTY. Для транспортов Ctrl-C отправлялся после установки
соединения; SIGINT/SIGTERM проверялись при прямом запуске приложения.
SSHD, временные ключи и tmux существовали только внутри одноразового контейнера;
его SSH слушал localhost, без опубликованных наружу портов.

PTY-стенд проверяет символы и расположение. Форма точек Braille и их читаемость
в конкретном пользовательском шрифте остаются свойством терминального эмулятора.

## Производительность

Release, 30 повторов, файловый кэш ОС прогрет, терминал 160×50, отношение сторон
ячейки 0.5. На каждом повторе документ открывается заново; кэш декодера документа
из предыдущего повтора не используется. Цифры относятся к **синтетическим**
фикстурам, не к произвольным книгам.

| Этап | JB2 2400×3500, медиана / p95, мс | Цветной IW44 320×240, медиана / p95, мс |
| --- | --- | --- |
| Открытие | 0.014 / 0.052 | 0.012 / 0.021 |
| Декодирование, яркость и порог | 1.811 / 2.971 | 0.909 / 1.229 |
| Символизация | 0.046 / 0.070 | 0.056 / 0.063 |
| Получение готового экрана из кэша | <0.001 / 0.001 | <0.001 / <0.001 |
| Формирование ANSI и запись в `/dev/null` | 0.025 / 0.081 | 0.023 / 0.033 |
| Открытие и первый рендер, без вывода | 1.874 / 3.102 | 0.975 / 1.313 |

В отдельной серии из 10 запусков процесса готовая большая страница в macOS PTY
появлялась за 10–22 мс после создания дочернего процесса. В Linux ARM PTY
синтетическая книга открылась за 12 мс; через tmux — за 21 мс; через локальный
SSH вместе с установкой соединения — за 123 мс. Это наблюдения стенда с шагом
опроса около 10 мс, а не гарантии сетевой задержки. Один первый запуск macOS
после перелинковки занял около секунды.

ANSI-бенчмарк не измеряет обработку текста графическим эмулятором и передачу
по сети. Интерактивный цикл Ratatui отправляет разницу экранов; бенчмарк ANSI
формирует все строки изображения. Для измерений на реальных документах:

```sh
cargo run --release --locked --example benchmark -- /path/to/book.djvu
DJVU_TUI_TIMINGS=1 ./target/release/djvu-tui /path/to/book.djvu
```

## CI и оставшиеся границы

В единственном workflow изменён только `push.paths-ignore: ['djvu-tui/**']`.
Каталоги selective builds и рецепты веб/Android не изменены; смешанные изменения
по-прежнему запускают обычный workflow. Это проверено по конфигурации, без
публикации и запуска GitHub Actions.

Бюджет 64 MiB относится к сохраняемым растрам и сеткам символов. Исходный файл,
активное декодирование и отображаемый экран в него не входят. Проверочные файлы
охватывают кодеки и геометрию; длительная проверка на большой пользовательской
библиотеке DjVu не проводилась.

## Экспериментальная мозаика 4×4

Для `Mardock01.djvu`, страница 2 (автоматический разворот), release на Apple M4,
160×50, прогретый файловый кэш, 30 повторов, последовательные серии:

| Этап | Braille медиана / p95, мс | Мозаика медиана / p95, мс |
| --- | --- | --- |
| Декодирование, яркость и порог | 3.346 / 3.997 | 7.117 / 17.209 |
| Символизация | 0.058 / 0.067 | 0.104 / 0.258 |
| Открытие и первый рендер, без вывода | 4.035 / 4.846 | 7.839 / 20.825 |
| Получение экрана из кэша | <0.001 / 0.001 | <0.001 / 0.001 |

Экспериментальный режим использует 4×4 отсчёта и таблицу ближайших шаблонов;
более подробный растр увеличивает стоимость декодирования. Это замеры одного
документа, без графической отрисовки терминала и без сетевой задержки. PTY-тест
проверил переключение всех трёх режимов, дизеринг, изменение размеров и инверсию.
Визуальная проверка Terminal.app, сравнение читаемости и проверка через tmux/SSH
для нового режима не проводились. Поэтому преимущество по качеству не установлено;
форма и доступность отдельных символов зависят от шрифта терминала.
