Это только первая стадия пайплайна:

**SUBTLEX-PL + KWJP → объединённый top 3000 польских лемм**

## 1. Источники данных

Используй только первичные/официальные источники.

### SUBTLEX-PL

SUBTLEX-PL — частотная база польских слов на основе субтитров фильмов и сериалов.

Предпочтительный актуальный источник:

https://osf.io/5a76z/

Это архив SUBTLEX-PL с файлами частот, описанных в:

Paweł Mandera, Emmanuel Keuleers, Zofia Wodniecka, Marc Brysbaert,
“SUBTLEX-PL: Subtitle-based word frequency estimates for Polish”,
Behavior Research Methods, 2015.

DOI:
https://doi.org/10.3758/s13428-014-0489-4

Оригинальная страница, указанная авторами публикации:

http://crr.ugent.be/subtlex-pl

SUBTLEX-PL содержит не только surface forms, но также информацию о lemma, POS, частоте lemma и contextual diversity.

ВАЖНО: сначала исследуй реальную схему актуального файла SUBTLEX-PL. Не угадывай названия колонок.

Если lemma frequency уже дана авторами, используй её.

Не суммируй колонку lemma frequency по всем word-form rows, если одно и то же значение повторяется для каждой формы одной леммы — это привело бы к многократному подсчёту.

Если готовой однозначной lemma frequency нет, аккуратно восстанови её из word forms и документируй алгоритм.

### KWJP

Используй Korpus Współczesnego Języka Polskiego — современный корпус польского языка 2011–2020.

Документация frequency lists:

https://kwjp.pl/lists/doc/about/en

Официальный GitHub:

https://github.com/ipipan/kwjp100-varia/tree/main/freqlists

Для нашей задачи нужен прежде всего файл:

`kwjp100-slowa-lemma-all.csv.gz`

Страница файла:

https://github.com/ipipan/kwjp100-varia/blob/main/freqlists/kwjp100-slowa-lemma-all.csv.gz

Прямой raw URL:

https://raw.githubusercontent.com/ipipan/kwjp100-varia/main/freqlists/kwjp100-slowa-lemma-all.csv.gz

Это список отдельных слов в представлении **lemma** по всему сбалансированному KWJP.

Не используй:

* n-gram lists;
* `orth` вместо `lemma`;
* отдельный fiction/factual/publicystyka список вместо `all`.

Из KWJP сохрани как минимум доступные поля:

* lemma;
* POS;
* raw frequency F;
* IPM;
* ARF;
* 1-DP;
* corpus rank.

Если реальные названия колонок отличаются, определить их из файла и описать mapping в README.

## 5. Нормализация лемм

Все строки должны быть Unicode UTF-8.

Не удаляй польские диакритики:

`ą ć ę ł ń ó ś ź ż`

Леммы должны храниться в нормальной польской орфографии.

Для итогового lemma key:

* trim whitespace;
* Unicode normalization NFC;
* lowercase там, где это лингвистически разумно.

Но исходное значение тоже сохрани при необходимости.

Не применяй stemming.

Не пытайся самостоятельно превращать польское слово в «корень».

Используй лемматизацию, уже предоставленную корпусом.

## 6. Очень осторожная фильтрация

Это candidate list для дальнейшей ручной/LLM-фильтрации, поэтому НЕ переусердствуй.

Удалить можно очевидный технический мусор:

* пустые значения;
* URL;
* email;
* токены, состоящие только из пунктуации;
* токены с очевидно повреждённой кодировкой;
* числа и чисто числовые токены;
* очевидные markup artifacts.

НЕ делать blacklist по длине.

Однобуквенные слова вроде:

`a`
`i`
`o`
`w`
`z`

являются важнейшими польскими служебными словами и должны остаться.

Не удалять:

* местоимения;
* предлоги;
* союзы;
* частицы;
* вспомогательные глаголы;
* разговорную лексику;
* ругательства только потому, что это ругательства.

Proper names желательно не удалять необратимо автоматически.

Если источник позволяет определить имя собственное, лучше добавить:

`suspected_proper_name = true`

и использовать это как отдельный флаг.

Для `top3000.csv` можно исключить только случаи, которые достаточно надёжно определены как имена собственные. Количество таких удалений должно быть отражено в статистике.

## 7. Работа с POS и омонимами

KWJP может содержать одинаковую орфографическую lemma с различными POS.

Нельзя просто потерять эту информацию.

Создай intermediate representation уровня:

`lemma + POS`

а затем lemma-level representation.

В итоговом списке должна быть одна строка на орфографическую лемму, но сохранить:

* `pos_primary`
* `pos_all`
* POS breakdown, если возможно.

Если одна lemma встречается как несколько POS, её частоты нужно агрегировать корректно.

При этом исходные POS-specific строки должны оставаться доступными в processed data для аудита.

## 8. Приведение частот к общей шкале

НИ В КОЕМ СЛУЧАЕ не складывай raw frequency SUBTLEX и raw frequency KWJP.

Размеры корпусов разные.

Основной сопоставимой величиной может быть frequency per million / IPM и логарифмическая Zipf-like шкала.

Если имеется IPM:

```python
zipf = log10(IPM) + 3
```

для IPM > 0.

Если SUBTLEX уже предоставляет авторский Zipf score, сохрани его как отдельную колонку и по возможности используй именно опубликованный показатель.

Сохраняй и исходные значения, и нормализованные.

## 9. Combined frequency score

Колода ориентирована прежде всего на практическое понимание повседневного польского.

Поэтому SUBTLEX должен иметь несколько больший вес, чем KWJP.

Default:

```text
SUBTLEX weight = 0.65
KWJP weight    = 0.35
```

Но веса должны быть параметрами командной строки.

Например:

```bash
python -m src.build_frequency_list \
    --top 3000 \
    --subtlex-weight 0.65 \
    --kwjp-weight 0.35
```

Не делай raw counts частью combined score.

Выбери статистически разумный способ объединения частот.

Предпочтительный baseline:

```text
combined_frequency =
    0.65 * normalized_subtlex_frequency +
    0.35 * normalized_kwjp_frequency
```

Но необходимо корректно решить проблему разницы шкал и отсутствующих значений.

Рассмотри и сравни как минимум два способа:

### A. Zipf/IPM weighted score

Сопоставимые log-frequency values.

### B. Weighted rank fusion

Например weighted Reciprocal Rank Fusion или percentile rank fusion.

Не усложняй ради усложнения.

Выбери один default после проверки результатов, а альтернативный score сохрани отдельной колонкой.

Объясни выбор в README.

## 10. Слова, отсутствующие в одном из корпусов

Не делай inner join.

Используй union.

Очень частое разговорное слово может иметь сильно отличающийся ранг в письменном корпусе и наоборот.

Поэтому отсутствие в одном источнике не означает автоматического удаления.

Для каждой lemma сохранить:

```text
in_subtlex
in_kwjp
```

и source-specific frequencies/ranks.

При combined ranking отсутствие значения должно обрабатываться явно и документированно.

Не превращай missing frequency в среднюю frequency.

## 11. Использовать contextual diversity / dispersion как диагностику

Если SUBTLEX предоставляет contextual diversity — сохрани её.

Для KWJP сохранить:

* ARF;
* 1-DP.

Не обязательно делать эти значения главным ranking criterion.

Но они полезны для обнаружения слов, которые имеют высокую raw frequency только из-за небольшого количества текстов.

Добавь диагностический флаг вроде:

`low_dispersion = true`

если слово подозрительно сконцентрировано.

Не удаляй его автоматически без веской причины.
