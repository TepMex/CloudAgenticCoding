# ear-eye-t — спецификация MVP

## Purpose

Личное Android-приложение для HONOR 400 (MagicOS 10, Android 16, API 36). Оно измеряет два вида использования телефона и честно показывает, где данных не хватает.

- **Глазное время** — устройство интерактивно, и экран блокировки не показан.
- **Ушное время** — в публичном списке активных плееров есть воспроизведение выбранной категории.

Приложение ставится через APK, работает без root и системных привилегий, хранит данные только на устройстве. Язык интерфейса — русский. Неподтверждённый промежуток не выдаётся за тишину и не добивается оценкой.

## Requirements

1. Считать глазное время по `UsageEvents`: `SCREEN_INTERACTIVE`, `SCREEN_NON_INTERACTIVE`, `KEYGUARD_SHOWN`, `KEYGUARD_HIDDEN`, `DEVICE_SHUTDOWN`, `DEVICE_STARTUP`.
2. На API 35+ запрашивать только эти типы через `UsageEventsQuery.Builder.setEventTypes()`.
3. Глазное время активно только при известном `screenInteractive == true` и `keyguardShowing == false`. Неизвестное начало не считается разблокировкой.
4. Не считать Always-On Display и экран блокировки. `isKeyguardLocked()` означает показ keyguard, а не требование PIN. Текущее состояние устройства не подставляется в историю.
5. Синхронизировать события экрана через WorkManager примерно раз в час, при запуске приложения и с перекрытием окна. Повторный импорт не удваивает события.
6. Считать ушное время по `AudioManager.registerAudioPlaybackCallback()` и `getActivePlaybackConfigurations()`. Не вызывать скрытые `isActive()` и `getPlayerState()`.
7. По умолчанию учитывать `USAGE_MEDIA` и `USAGE_GAME`. Ассистент, навигацию и accessibility можно включить. Уведомления, звуки интерфейса, будильники, рингтон и разговор не учитывать.
8. Несколько плееров одновременно дают один интервал. Повтор того же агрегатного состояния новый интервал не открывает.
9. Держать callback внутри `NotificationListenerService`. Содержимое чужих уведомлений не читать и не сохранять. Foreground Service в MVP нет.
10. Если мониторинг оборвался, не продлевать аудиоинтервал через неподтверждённый промежуток. Помечать его неизвестным и читать состояние заново.
11. Heartbeat примерно раз в 5 минут без wake lock и exact alarm. Промежуток дольше 30 минут между подтверждениями не считается непрерывным наблюдением.
12. Считать Eye, Ear, Eye Only, Ear Only, Overlap, Union, покрытие и неизвестное время. `Union = Eye + Ear − Overlap` только там, где известны оба измерения.
13. Делить интервалы по локальным дням через `java.time` и `ZoneId`, включая смену пояса и переход на летнее или зимнее время.
14. Показывать сегодня, вчера и выбранную дату, шкалу, диагностику и экспорт JSON/CSV через Storage Access Framework.
15. Объяснить Usage Access, Notification Listener, Restricted Settings и ограничения MagicOS до перехода в системные настройки.
16. Не использовать интернет, микрофон, root, скрытые API, аналитические SDK и автоматический обход ограничений Android.

## Interfaces

- UI: одна activity, три вкладки — «Сегодня», «Диагностика», «Доступ».
- Системные экраны: `Settings.ACTION_USAGE_ACCESS_SETTINGS`, `Settings.ACTION_NOTIFICATION_LISTENER_SETTINGS`, карточка приложения, список настроек батареи. Если activity нет, открывается следующий вариант из этого списка.
- Служба: `MonitoringNotificationListenerService` с `BIND_NOTIFICATION_LISTENER_SERVICE`.
- Фон: `ScreenSyncWorker`, периодическая работа 1 час и разовая при открытии UI. Приёмник `TIME_SET` и `TIMEZONE_CHANGED` только пишет диагностику и просит новый снимок аудио.
- Экспорт: `ACTION_CREATE_DOCUMENT`, MIME `application/json` и `text/csv`. Разрешения на все файлы нет.
- База: Room, файл `ear-eye.db`, версия схемы 1. Каталог схем: `app/schemas`.

Категории звука меняют только новые наблюдения: прошлые переходы уже записаны как агрегат.

## Data model

События и интервалы, без посекундного счётчика.

- `screen_events` — тип, время, порядковый номер внутри одной миллисекунды. Уникальный ключ `(timestamp, type, ordinal)`. Имена пакетов не хранятся.
- `audio_transitions` — переход агрегата активен/неактивен, wall-clock, `elapsedRealtime`, номер загрузки, сессия.
- `monitoring_sessions` — подключение, последнее подтверждение, callback, снимок, heartbeat, причина завершения.
- `diagnostic_events` — кольцо последних 100 записей без текста уведомлений.
- `sync_state` — время успешной синхронизации и доверенный горизонт экрана.
- `audio_settings` — включённые категории.
- `data_generation` — счётчик, по которому UI перечитывает статистику.

Интервалы полуоткрытые: `[start, end)`. Длительность внутри одной загрузки берётся из монотонных часов. На календарь интервал кладётся от wall-clock якоря сессии: `connectedWall + (elapsed - connectedElapsed)`.

Глазное состояние экстраполируется только до конца последнего успешного запроса UsageEvents. Пара `DEVICE_SHUTDOWN` … `DEVICE_STARTUP` без противоречащих экранных событий — известное выключение, не тишина «на слух» и не неизвестность. Незакрытое выключение до «сейчас» не дотягивается.

## UI / UX

Главный экран: подтверждённые глазное и ушное время, пересечение, общее время, только экран, только звук, покрытие, неизвестное время, статус мониторинга, время последнего подтверждения и шкала. При неполных данных показывается предупреждение. Числа подписаны как подтверждённые.

Диагностика: версия Android, производитель и модель, доступы, keyguard, текущий звук, callback, heartbeat, снимок, синхронизация экрана, последние события, экспорт.

Доступы: зачем каждый доступ, почему уведомления не читаются, Restricted Settings, фон MagicOS, переключатели категорий и кнопки системных экранов.

## Out of scope

Аккаунты, сервер, облако, имя текущего плеера через скрытые API, аналитика по приложениям, AI, виджеты, Wear OS, лимиты и уведомления о них, блокировка приложений, управление телефоном, микрофон, foreground service, wake lock, exact alarm, интернет.

Круглосуточная надёжность на MagicOS не считается доказанной, пока её не проверят на HONOR 400 по `docs/HONOR_400_TEST_PLAN.md`.

## Acceptance criteria

- Проект открывается в Android Studio и собирает debug APK при установленном Android SDK 36.
- JVM-тесты дают точные миллисекунды для сценариев экрана, аудио, пересечения, полуночи, перехода часов, обрыва мониторинга, перезагрузки, повторной синхронизации и неизвестных интервалов.
- Повторный импорт одного и того же окна UsageEvents не увеличивает число событий.
- Неполные данные видны в статистике и не подменяются нулём.
- Манифест не содержит `INTERNET`, `RECORD_AUDIO`, `READ_MEDIA_AUDIO`, `QUERY_ALL_PACKAGES`, `SYSTEM_ALERT_WINDOW` и accessibility service.
- В коде нет reflection и вызовов скрытых audio API.
