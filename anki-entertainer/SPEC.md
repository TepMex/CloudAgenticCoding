# anki-entertainer — Specification

## Overview

**anki-entertainer** is an Android companion app for [AnkiDroid](https://github.com/ankidroid/Anki-Android). While reviewing flashcards, the user can open the app via a custom URI and receive several short text chunks generated by randomly selected LLMs (OpenAI-compatible API, bring-your-own-key).

| Field | Value |
|-------|-------|
| App name | anki-entertainer |
| Package | `com.tepmex.ankientertainer` |
| Min SDK | 34 (Android 14+) |
| Target SDK | 35 |

## Purpose

During AnkiDroid review, a card template or note type can link to anki-entertainer with the vocabulary under study. The app generates entertaining or contextual mini-texts around that vocabulary using configurable prompts and multiple remote models.

## Deep link (AnkiDroid → anki-entertainer)

### URI scheme

Register custom scheme **`ankientapi`** with host **`x-callback-url`** (x-callback-url style inter-app callback).

**Canonical form:**

```
ankientapi://x-callback-url?q={VOCAB}
```

**Also accepted:**

```
ankientapi://x-callback-url/q={VOCAB}
```

- `{VOCAB}` — URL-encoded vocabulary string from the Anki card (query parameter `q` or path segment after `/q=`).
- App must decode the value (UTF-8) and use it as the session vocabulary key.

### AnkiDroid integration example

In a card template field:

```html
<a href="ankientapi://x-callback-url?q={{Front}}">Entertain me</a>
```

Or with path form:

```html
<a href="ankientapi://x-callback-url/q={{Front}}">Entertain me</a>
```

### Android manifest

- `VIEW` intent filter on `MainActivity`
- `android:scheme="ankientapi"`, `android:host="x-callback-url"`
- `DEFAULT` + `BROWSABLE` categories

## Functional requirements

### 1. Adjustable generation prompt

- Settings screen exposes a **chunk prompt** template.
- Placeholder **`{QUERY}`** is replaced with the vocabulary from the deep link before each LLM call.
- Default prompt instructs the model to produce one short, self-contained text chunk related to the vocabulary.

### 2. Model list and BYOK settings

Settings store:

| Setting | Description |
|---------|-------------|
| API base URL | OpenAI-compatible root (e.g. `https://api.openai.com`) |
| Access token | Bearer token (optional if the endpoint does not require auth) |
| Model list | One or more model names; **each new chunk** uses a **randomly picked** model from this list |

### 3. Adjustable chunk count

- Settings: **target chunk count** (integer, default 5).
- This is the number of chunks shown for a vocabulary session (liked + newly generated combined).

### 4. Custom URI registration

- As described in [Deep link](#deep-link-ankidroid--anki-entertainer).
- Opening the URI launches `MainActivity` with the vocabulary; if the app is already open with a different vocab, switch to the new session.

### 5. Like (mark) chunks per vocabulary

- User can **like** any chunk (heart / mark control).
- Liked chunks are **persisted per vocabulary** (`{VOCAB}` string as key).
- On next open for the same vocabulary, **saved liked chunks appear first**, then newly generated chunks fill the remainder up to the target count.
- **Liked chunks do not consume the generation quota**: if target count is 5 and 2 chunks are already liked, generate **3** new chunks (total displayed = 5).

### 6. Undo like

- User can **unlike** a previously liked chunk; it is removed from persistent storage for that vocabulary.
- Unlike does not auto-generate a replacement; user may tap **Regenerate** to fill gaps.

### 7. Regenerate new chunks only

- **Regenerate** button replaces **only non-liked (session-generated) chunks** with fresh LLM output.
- Liked chunks are kept unchanged and remain visible.

## Non-functional requirements

- **Offline**: app requires network for LLM calls; show clear error if API is unreachable or misconfigured.
- **Privacy**: API keys stored locally in DataStore on device only.
- **Cancellation**: in-flight generation can be stopped; partial results remain until regenerate.

## Data model

### Settings (`AppSettings`)

```kotlin
data class AppSettings(
    val llmBaseUrl: String,
    val llmToken: String,
    val modelNames: List<String>,
    val chunkPrompt: String,      // contains {QUERY}
    val chunkCount: Int,
)
```

### Chunk (`TextChunk`)

```kotlin
data class TextChunk(
    val id: String,               // UUID
    val text: String,
    val isLiked: Boolean,
    val modelName: String?,       // model used when generated
)
```

### Liked-chunk persistence

- DataStore JSON map: `vocab → List<{id, text, modelName}>`
- Vocabulary key = exact decoded string from deep link.

## UI

### Main screen

- Toolbar: app title, settings menu.
- Vocabulary headline (current `{VOCAB}`).
- Status line + progress during generation.
- **Regenerate** and **Stop** actions.
- Scrollable list of chunks; each row:
  - chunk text (selectable)
  - like / unlike toggle
  - subtle badge if chunk is saved (liked)

### Settings screen

- API base URL
- Access token (password field)
- Model names (multi-line: one model per line)
- Chunk prompt (`{QUERY}` hint)
- Chunk count (number)
- Save

### Empty / launch states

- Launcher open without URI: hint explaining AnkiDroid deep link format.
- Missing API config: prompt to open Settings.

## LLM integration

- OpenAI-compatible `POST {baseUrl}/v1/chat/completions`
- Per chunk: one request, `temperature ≈ 0.8`
- System message: expanded chunk prompt (`{QUERY}` → vocab)
- User message: brief instruction to output a single short chunk (no markdown wrapper)

## Out of scope (v1)

- Direct AnkiDroid content-provider integration (vocab comes only via URI).
- On-device / local LLM.
- Syncing liked chunks across devices.
- Editing chunk text manually.

## Acceptance criteria

1. Tapping `ankientapi://x-callback-url?q=你好` opens the app and shows/generates chunks for `你好`.
2. Settings changes persist across restarts.
3. Liked chunks reappear for the same vocab on next launch; new chunks fill up to configured count.
4. Regenerate updates only non-liked chunks.
5. Unlike removes chunk from saved set for that vocab.
