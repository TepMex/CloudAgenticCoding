# План счетов — SPEC

## Purpose

Учебный справочник плана счетов РФ для человека, который начинает разбирать дебет и кредит. Сайт показывает коммерческий план № 94н (не банки и не бюджет) и раскладывает проводки каждого счёта по четырём клеткам шпаргалки: актив с активом, пассив с пассивом и две смешанные пары.

## Requirements

1. Показать 62 балансовых счёта матрицей 10×10. Номер счёта — это ряд и столбец: 51 стоит в ряду 5 и столбце 1. Номера, которых нет в плане, остаются пустыми клетками.
2. Забалансовые 001–011 показать отдельно, не в клетках 01–11.
3. Открытие счёта показывает смысл, что означает дебет, что означает кредит, особенности и источники.
4. Двойные проводки счёта стоят в четырёх клетках шпаргалки, в том же порядке и с теми же знаками, что на учебной схеме «дебет и кредит»:
   - актив + / актив − (ДА / КА);
   - пассив + / пассив − (ДП / КП);
   - актив + / пассив + (ДА / КП);
   - актив − / пассив − (ДП / КА).
5. У проводки видно, какая сторона растёт и какая уменьшается. Текущий счёт выделен. Второй счёт открывается по ссылке.
6. Сторно остаётся в клетке той же пары и помечено как отрицательная сумма, а не как обратная проводка.
7. Забалансовые записи односторонние: «приняли на контроль» и «сняли с контроля», без четырёх клеток.
8. Активно-пассивный счёт ставится на активную или пассивную сторону по субсчёту и обычному сальдо. Оговорка написана на странице счёта.
9. Поиск по номеру и названию оставляет форму матрицы: неподходящие счета бледнеют, пропуски остаются пропусками.

## Interfaces

| Interface | Detail |
| --------- | ------ |
| Web | Bun собирает `index.html` в `dist/`. Маршруты — хеш: `#` матрица, `#51` счёт, `#a51` тот же счёт |
| Pages | `/plan-schetov/` на GitHub Pages. Локальная сборка без `GH_PAGES_PUBLIC_PATH` кладёт относительные пути |
| Catalog | `data/source.html` → `scripts/extract.py` → `src/data/accounts.json` |
| Dev | `bun dev` на `http://127.0.0.1:4177` |

## Data model

Счёт: код, имя, вид (`active`, `passive`, `active-passive`), признак забалансового, смысл, текст дебета, текст кредита, особенности, источники, список проводок.

Проводка: дебет и/или кредит (субсчёт сохраняется строкой), текст, метки, признак сторно. Односторонняя проводка есть только у забалансового счёта.

Клетка проводки считается не хранится. Её задаёт полюс дебетуемого и кредитуемого счёта:

- активный и забалансовый — актив;
- пассивный — пассив;
- активно-пассивный — правило субсчёта в `src/lib/poles.ts` (60.02 актив, 60 обычный долг пассив, 90.01 пассив, 90.02 актив, 79 дебет актив / кредит пассив, и остальные оговорки рядом с текстом для страницы).

Состояние в браузере не хранится.

## UI / UX

1. Сверху шпаргалка: актив и пассив, четыре клетки с примерами, полоса «как запомнить».
2. Под ней матрица. Цвет клетки — вид счёта: синий актив, фиолетовый пассив, переход — активно-пассивный. Буквы А / П / АП дублируют цвет.
3. Страница счёта повторяет четыре клетки. Внутри проводки дебет и кредит покрашены так же: синий актив, фиолетовый пассив, плюс и минус по шпаргалке.
4. На узком экране матрица листается вбок, клетки шпаргалки встают столбцом. С телефона читается и матрица, и проводки.

## Out of scope

- Колода Anki и её импорт.
- Редактор рабочего плана, суммы, ставки, проводки «от себя».
- Планы банков и бюджетной сферы.
- Учётная политика и советы по конкретной организации.
- Вход, сервер, сохранение прогресса.

## Acceptance criteria

1. `bun test` в `plan-schetov` сверяет JSON с HTML, считает 62+11 счетов, проверяет координаты матрицы и четыре клетки шпаргалки на парах «материалы за наличные», «краткосрочный долг в долгосрочный», «товар от поставщика», «погашение кредита с расчётного счёта», а также на живых проводках 10/60, 41/60, 66/51 и зачёте 60.01/60.02.
2. `bun run build` создаёт `dist/index.html`.
3. В браузере матрица показывает пропуски, счёт 10 открывает поступление от поставщика в клетке ДА/КП, счёт 66 — погашение кредита в клетке ДП/КА, счёт 001 — две односторонние записи.
